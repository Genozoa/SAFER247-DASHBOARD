SAFER 247 - WINDOWS DEVELOPMENT STARTUP
======================================

Operate from the GPT-branch2 repository root. Keep your local .env private.

1. Install Python 3.11+, PostgreSQL/PostGIS, Node.js 22, npm, and Git.
2. Copy .env.example to .env and set DATABASE_URL, APP_ENV, and local radio settings.
   No personnel registration code is required.
   Keep RADIO_ENABLED=false for UI-only development.
3. Back up your current database. Load DATABASE_URL from the root .env into the
   current PowerShell process. From backend/:
       python -m alembic -c alembic.ini current
       python -m alembic -c alembic.ini upgrade head
   Expected head: 0010_remove_registration_code.
4. Install backend dependencies:
       cd backend
       py -m venv .venv
       .\.venv\Scripts\Activate.ps1
       python -m pip install -r app/radio_lab/requirements.txt
5. If synthetic data is needed, configure DEMO_OPERATOR_CALL_SIGN=Demo
   and DEMO_OPERATOR_PASSWORD in .env and load them into your process:
       python -m app.auth.seed_demo --confirm-demo-seed
   Apply backend/database/seed_demo.sql in a disposable development database.
6. Start FastAPI from backend/:
       python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
7. In a second PowerShell terminal:
       cd frontend
       npm ci
       npm run dev
   Browse http://localhost:3000 and API docs at http://127.0.0.1:8000/docs.
8. Register with a call sign and strong password. No approval or code step.
   Anyone with endpoint access could self-register. Keep operational
   deployments private and restrict registration before public exposure.
9. Verify:
       cd backend; python -m pytest -q
       cd frontend; npm test; npm run build

The Demo account cannot transmit radio data. Radio uses the existing
WAV/spool architecture, not TCP KISS. See docs/LDRRMO_DEPLOYMENT.md.
